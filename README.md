# AhriNode tool

Интерактивный скрипт первичной настройки сервера под ноду Remnawave и набор
вспомогательных утилит вокруг неё.

Написан на Python, работает через меню с галочками: вы отмечаете нужные блоки,
видите сводку и подтверждаете запуск. Ничего не выполняется до подтверждения.

Рассчитан на Debian/Ubuntu (`apt`, `systemd`), запускается от root.

## Запуск

```bash
curl -fsSL https://raw.githubusercontent.com/kifchandr/ahrinodemaker/main/ahrinodemaker | sudo python3
```

Либо в главном меню выбрать **«Установить короткие команды `ahri` и
`ahrinode`»** — скрипт пропишется в `/usr/local/bin`, и дальше достаточно:

```bash
sudo ahri          # или sudo ahrinode, или sudo ahrinodemaker
```

Пункт показывается, только пока команда не установлена. То же самое вручную:

```bash
sudo curl -fsSL https://raw.githubusercontent.com/kifchandr/ahrinodemaker/main/ahrinodemaker \
     -o /usr/local/bin/ahrinodemaker && sudo chmod +x /usr/local/bin/ahrinodemaker \
     && sudo ln -sf /usr/local/bin/ahrinodemaker /usr/local/bin/ahri \
     && sudo ln -sf /usr/local/bin/ahrinodemaker /usr/local/bin/ahrinode
```

При первом запуске скрипт доустановит две Python-библиотеки для самого меню
(`rich`, `questionary`). Пакеты для ноды не трогаются, пока вы не подтвердите
выбор блоков.

### Аргументы

`--panel-ip АДРЕС` — адрес или подсеть панели: порт 2222 откроется только для
них, и вопрос при настройке UFW задаваться не будет. Удобно при развёртывании
нескольких нод.

```bash
curl -fsSL https://raw.githubusercontent.com/kifchandr/ahrinodemaker/main/ahrinodemaker \
  | sudo python3 - --panel-ip 203.0.113.10
```

Дефис после `python3` обязателен: он говорит интерпретатору читать скрипт со
стандартного ввода, а остальное считать аргументами скрипта. Установленной
команде аргументы передаются как обычно: `sudo ahri --panel-ip 203.0.113.10`.

Адреса в коде нет: если аргумент не задан, скрипт спросит при настройке UFW, а
при пропуске вопроса порт 2222 останется открытым для всех.

## Структура меню

```
Главное меню
├── Remnawave Node — настройка сервера под ноду
├── Tools — вспомогательные утилиты
│   ├── Remnawave Backup & Restore (distillium)
│   │   └── Удаление старых бэкапов Google Drive
│   ├── SOCKS5-прокси Dante
│   └── Проверить обновления сторонних скриптов
├── Тесты — диагностика сервера
│   ├── Тест регионов (ipregion.xyz)
│   ├── Проверка скорости — Европа (speedtest)
│   ├── Проверка скорости — Россия (iperf3)
│   └── Доступен ли Telegram
└── Выход
```

На каждом уровне есть «← Назад», Ctrl+C возвращает на уровень выше.

## Раздел «Remnawave Node»

Перед показом списка скрипт проверяет, что уже настроено на сервере: настроенные
блоки идут **без галочки**, чтобы не выполнять их повторно. Отметить вручную и
прогнать заново можно всегда. Также выводится сводка: свободное место на диске,
текущее расписание автоперезагрузки и путь к compose ноды.

Реестр образов при входе в меню не опрашивается — это добавляло несколько секунд
ожидания, а решение о том, обновлять ли ноду, всё равно за вами.

| Блок | Что делает |
|---|---|
| Установка пакетов | `fail2ban`, `ufw`, `unattended-upgrades`, `cron`, `psmisc`; включает автообновления безопасности |
| Установка Remnawave Node | ставит Docker, спрашивает `SECRET_KEY` и порт (по умолчанию 2222), создаёт `/opt/remnanode/docker-compose.yml` (сразу с volume для логов), готовит `/var/log/remnanode/{access,error}.log`, настраивает ротацию логов и поднимает контейнер. Пункт появляется, **только если ноды на сервере нет** |
| Часовой пояс + cron | `Europe/Moscow` и автоперезагрузка в 03:00 — ежедневно или по понедельникам (на выбор) |
| Fail2Ban | jail `sshd`: 5 попыток за 10 минут, бан на 12 часов |
| UFW | входящие запрещены, исходящие разрешены, `limit ssh`, открыты 80/443/8443/9999; порт 2222 (панель → нода) можно ограничить адресом панели, спрашивается при настройке; можно добавить свои порты |
| Сеть | `nf_conntrack` + `sysctl`: BBR + fq, увеличенные буферы и очереди, keepalive, отключение IPv6, `swappiness=10` |
| Логи remnanode | каталог `/var/log/remnanode`, ротация через logrotate, добавление volume в `docker-compose.yml` ноды. Пункт для нод, установленных **не этим скриптом**: при установке ноды отсюда всё это уже сделано, и пункт скрывается |
| Обновление remnanode | `docker compose pull` + пересоздание контейнера. Пункт появляется, если нода установлена, и идёт **без галочки** — тянуть образ при каждом прогоне незачем |
| Автообновление ноды | `@reboot`-задача обновляет образ при каждой загрузке сервера, с журналом в `/var/log/remnanode/auto-update.log`. **По умолчанию включено** |
| Hysteria2 (QUIC) | при отсутствии сертификата выпускает его через certbot, монтирует `/dev/shm` в контейнер, кладёт туда сертификаты, открывает `443/udp`, заводит cron на их обновление и генерирует заготовку inbound'а для панели. **По умолчанию выключен** |
| WARP | поднимает контейнер `caomingjun/warp` с SOCKS5 на `127.0.0.1:40000`, дожидается туннеля и генерирует outbound + правило маршрутизации для панели. Нужен, когда сервис режет IP дата-центров: Gemini, ChatGPT, Spotify. **По умолчанию выключен** |
| Psiphon | альтернатива WARP: контейнер `swarupsengupta2007/psiphon` с SOCKS5 на `127.0.0.1:41080`, страна выхода на выбор — 31 страна плюс ввод произвольного кода. Пригодится, если адреса WARP у сервиса на плохом счету. При смене страны прежний `psiphon.config` удаляется — иначе переменные окружения не применятся. **По умолчанию выключен** |
| Блокировка торрентов | `tblocker` + резервный egress-фильтр на nftables (порты 6881–6889, 51413) + справка по настройке панели |
| TrafficGuard-auto | установка [TrafficGuard-auto](https://github.com/DonMatteoVPN/TrafficGuard-auto) — защита от сканеров и ботов, меню `rknpidor` |

Пункт **Hysteria2** идёт без галочки: это дополнительный транспорт, он требует
TLS-сертификата и ручного включения inbound'а в панели Remnawave. Если
сертификата нет, скрипт спросит домен и выпустит его через certbot в режиме
standalone — A-запись домена должна указывать на этот сервер, а порт 80 быть
свободным. Удостоверяющий центр выбирается: Let's Encrypt, Buypass Go SSL,
ZeroSSL или Google Trust Services. Последним двум нужны EAB-ключи из личного
кабинета, Buypass и ZeroSSL требуют e-mail. Привязки к одному УЦ нет —
если конкретный откажет, можно перезапустить блок и выбрать другой.
Скрипт готовит только серверную часть — сертификаты в `/dev/shm`, порт и
автообновление; сам inbound добавляется в конфиг ноды через панель.

Логи ноды растут постоянно, поэтому ротация настраивается сразу при установке —
отдельный блок для этого выбирать не нужно. А вот блокировка торрентов остаётся
отдельным пунктом: она подключает сторонний apt-репозиторий и без настройки
плагина в панели Remnawave не работает.

Обновление системы (`apt update && apt upgrade`) выполняется автоматически перед
блоками, которые ставят пакеты, и пропускается, если выбраны только «лёгкие»
блоки вроде часового пояса.

Если блок падает, выполнение не прерывается: остальные блоки отрабатывают, а в
конце выводится список сбоев с текстом ошибки.

### Файлы, которые создаёт раздел

- `/etc/fail2ban/jail.local`
- `/etc/sysctl.d/99-vpn.conf`, `/etc/modules-load.d/nf_conntrack.conf`, `/etc/modprobe.d/nf_conntrack.conf`
- `/etc/logrotate.d/remnanode`
- `/etc/systemd/system/torrent-egress-filter.{service,timer}`
- `/opt/remnanode/apply-torrent-egress-filter.sh`, `/opt/remnanode/panel-torrent-block-config.json`
- `/opt/remnanode/panel-hysteria-inbound.json` — заготовка inbound'а Hysteria2
  с подставленным доменом, для вставки в конфиг ноды через панель
- `/opt/warp/docker-compose.yml` и `/opt/remnanode/panel-warp-outbound.json` —
  только при включении WARP
- `/opt/psiphon/docker-compose.yml` и `/opt/remnanode/panel-psiphon-outbound.json` —
  только при включении Psiphon
- `/opt/tblocker/config.yaml`
- `/opt/remnanode/auto-update.sh` — при включённом автообновлении ноды
- `/opt/remnanode/docker-compose.yml` — только при установке ноды. Содержит
  `SECRET_KEY`, поэтому создаётся с правами `0600`
- `/var/log/remnanode/access.log`, `/var/log/remnanode/error.log` — пустые файлы
  под логи ноды. Существующие логи не перезаписываются

Перед перезаписью существующего файла создаётся копия `<файл>.bak-<дата>`, запись
атомарная. Если содержимое уже нужное — файл не трогается и копия не плодится.

## Раздел «Tools»

### Remnawave Backup & Restore

Установка и запуск [distillium/remnawave-backup-restore](https://github.com/distillium/remnawave-backup-restore)
— бэкап и восстановление панели и базы, отправка в Telegram, Google Drive или S3.
Скрипт разворачивается в `/opt/rw-backup-restore` и добавляет команду `rw-backup`.

### SOCKS5-прокси Dante

Установка и настройка [Dante](https://www.inet.no/dante/) — SOCKS5-сервера с
авторизацией по логину и паролю. Выбран потому, что пакет `dante-server` есть в
репозиториях Debian/Ubuntu и версия 1.4 умеет авторизацию и правила доступа;
`3proxy` в репозиториях Ubuntu отсутствует, а `microsocks` поддерживает лишь
одного пользователя без ACL.

Возможности:

- установка и перенастройка: порт (по умолчанию 1080) и список адресов,
  которым разрешено подключаться — можно перечислить несколько через запятую,
  адреса и подсети;
- добавление, удаление пользователей и смена пароля — пароль можно задать
  свой либо сгенерировать;
- параметры подключения и проверка работы через сам прокси;
- автозапуск: служба включается в systemd, а drop-in добавляет ожидание сети
  и перезапуск при сбое — иначе `external:` по имени интерфейса может не
  разрешиться на загрузке, и прокси молча не поднимется;
- полное удаление вместе с учётными записями.

Пользователи создаются системными, с `nologin` и без домашнего каталога: Dante
1.4 проверяет их через PAM и собственной базы не имеет. Пароль передаётся
`chpasswd` через stdin, а не аргументом — иначе он был бы виден в `ps`.

> **Логин и пароль в SOCKS5 передаются открытым текстом.** Ограничение по
> адресу при настройке — не придирка, а основная защита; открытый на весь мир
> порт переберут.

### Проверить обновления сторонних скриптов

Сравнивает зафиксированные копии из `vendor/` с текущими версиями у авторов и
показывает, где вышла новая версия. См. раздел «Сторонние скрипты» ниже.

### Удаление старых бэкапов Google Drive

Подменю для очистки папки Google Drive от старых бэкапов. Использует те же
OAuth-доступы, что и backup-restore, — берёт их из `/opt/rw-backup-restore/config.env`,
отдельная авторизация не нужна.

Возможности:

- установка скрипта в `/opt/rw-backup-restore/gdrive-cleanup.sh`;
- настройка ID папки и срока хранения (по умолчанию 30 дней);
- **пробный прогон** — показывает, что было бы удалено, ничего не трогая;
- реальный запуск: файлы перемещаются в корзину Google Drive, а не стираются;
- ежедневный запуск по cron в выбранный час и снятие его.

Запись в crontab помечается отдельным маркером: чужие задачи и запись
автоперезагрузки сохраняются, повторная настройка не создаёт дубликатов.
Лог пишется в `/opt/rw-backup-restore/gdrive-cleanup.log`.

Для очистки нужны `curl` и `jq` — скрипт доустановит их сам.

## Раздел «Тесты»

Диагностика сервера. Ничего не настраивают и не меняют — только показывают
текущее состояние.

| Тест | Что показывает |
|---|---|
| Тест регионов | как разные сервисы определяют местоположение адреса сервера — скрипт [Davoyan/ipregion](https://github.com/Davoyan/ipregion), он же раздаётся с `ipregion.xyz` |
| Скорость, Европа | `speedtest-cli` до ближайших серверов Ookla |
| Скорость, Россия | `iperf3` до российских серверов из списка [itdoginfo/russian-iperf3-servers](https://github.com/itdoginfo/russian-iperf3-servers) |
| Доступен ли Telegram | ответ `core.telegram.org` и `api.telegram.org` с кодом, временем и адресом |

Два теста выполняют сторонние скрипты, и они тоже зафиксированы в `vendor/` с
проверкой sha256 — исполняются от root, значит подчиняются тому же правилу, что
и установщики. Плата за это: список проверяемых сервисов и список серверов
iperf3 зашиты в копиях и со временем устаревают, поэтому за ними стоит следить
через **Tools → Проверить обновления сторонних скриптов**.

Установщик `iperf3` спрашивает, поднимать ли демон. Ответ задаётся заранее через
`debconf-set-selections`, иначе `apt` встал бы на диалоге.

## Сторонние скрипты

Чужие установщики **не скачиваются из репозиториев авторов во время работы**.
Их копии зафиксированы в каталоге `vendor/` этого репозитория, а эталонные
sha256 зашиты в сам `ahrinodemaker`. Перед запуском копия проверяется по хешу:
при несовпадении установка прерывается с ошибкой.

Это значит, что новый коммит в чужом репозитории не может незаметно изменить
то, что выполняется от root на вашем сервере.

| Скрипт | Проект |
|---|---|
| `vendor/install-trafficguard.sh` | [DonMatteoVPN/TrafficGuard-auto](https://github.com/DonMatteoVPN/TrafficGuard-auto) |
| `vendor/backup-restore.sh` | [distillium/remnawave-backup-restore](https://github.com/distillium/remnawave-backup-restore) |
| `vendor/ipregion.sh` | [Davoyan/ipregion](https://github.com/Davoyan/ipregion) — он же раздаётся с `ipregion.xyz` |
| `vendor/iperf3-ru-speedtest.sh` | [itdoginfo/russian-iperf3-servers](https://github.com/itdoginfo/russian-iperf3-servers) |

Метаданные копий — в [`vendor/manifest.json`](vendor/manifest.json).

### Обновление копии

Пункт меню **Tools → Проверить обновления сторонних скриптов** сравнивает копии
с апстримом и сообщает, где вышла новая версия. Обновление осознанное, в три шага:

1. скачать новый файл по `upstream_url` из `vendor/manifest.json`;
2. положить его в `vendor/`;
3. обновить `sha256` в `vendor/manifest.json` **и** в словаре `VENDOR` внутри
   `ahrinodemaker`.

Если обновить файл и забыть про хеш — установка перестанет работать. Это
задумано: расхождение означает, что содержимое изменилось без ведома автора
скрипта.

### Что осталось внешним

Вендоринг покрывает верхний уровень, но не всю цепочку:

- `install-trafficguard.sh` — обёртка: при установке сама тянет
  `dotX12/traffic-guard` и списки блокировок `shadow-netlab/traffic-guard-lists`;
- `backup-restore.sh` умеет **обновлять сам себя** из апстрима — после этого на
  сервере окажется версия автора, а не зафиксированная здесь;
- `tblocker` ставится пакетом из apt-репозитория `repo.remna.dev` с проверкой
  GPG-подписи;
- блок установки ноды ставит Docker официальным установщиком `get.docker.com`,
  если Docker в системе нет.

Сама установка ноды выполняется нативно, без стороннего скрипта: конфигурация
генерируется скриптом и запускается через `docker compose`.

## Требования

- Debian или Ubuntu с systemd
- root (`sudo`)
- Python 3.9+
- Доступ в интернет

## Важно

- **Проверьте порт SSH перед блоком UFW.** Правила открывают стандартный SSH
  (порт 22). Если SSH перевешен на другой порт и он не добавлен в
  дополнительные порты, после включения firewall доступ к серверу будет потерян.
- **Адрес панели для порта 2222 задан в коде** (константа в блоке `block_ufw`).
  При переезде панели на другой IP правило нужно поправить, иначе нода перестанет
  отвечать панели.
- **Блок cron включает автоматическую перезагрузку сервера** в 03:00. Если это
  нежелательно — не отмечайте его.
- Блок сети **отключает IPv6**.
- Блок торрентов готовит только серверную часть. В панели Remnawave нужно
  включить плагин Torrent Blocker, добавить правила маршрутизации, логирование в
  `/var/log/remnanode/access.log` и sniffing на inbound'ах — образец конфигурации
  скрипт сохраняет в `/opt/remnanode/panel-torrent-block-config.json`.
